# 两个人

只给一对情侣用的私密网页应用。两个人、两台 iPhone、一个只有你们能打开的小站。界面是简体中文，手机竖屏优先。

数据放在你自己的服务器上：SQLite 加本地照片。没有第三方统计，也没有广告。不做位置共享。

## 功能

- 首页显示「在一起第 N 天」。开始那天算第 1 天。纪念日可以增删改，并显示下一次还有几天。
- 共同相册。上传时压缩成 JPEG，并生成缩略图。支持 iPhone 的 HEIC。
- 共同日记。每篇可以选「仅自己可见」或「双方可见」，可以附心情和一张照片。
- 恋爱清单。预置了 24 条（例如「一起看日出」），也可以自己加。勾选完成时可以写一句、附一张照片。
- 每日一问。题库 72 题，按日期抽一题。两个人都回答之后，才能看到对方的答案。
- 网页推送。纪念日当天和前一天提醒；对方发布了新的相册、双方可见的日记或清单完成时通知。私密日记不会通知对方。

## 本地运行

需要 Node.js 22 或更新版本。

```bash
./start.sh
```

第一次会安装依赖，并在没有 `.env` 时从 `.env.example` 复制一份。浏览器打开：

```text
http://127.0.0.1:8787
```

应用只监听本机。手机要访问时，用下面的 HTTPS 反向代理，不要把 8787 直接暴露到公网。

跑测试：

```bash
npm test
```

## 第一次使用

打开网站后，一起填写在一起的日期、时区和两个账号。创建完成后记下两个用户名，各自登录。注册只此一次，之后不能再加账号。

密码至少 8 位。登录状态保存在 HttpOnly Cookie 里，默认 30 天，从登录那天起算，不会因为继续使用而延长。退出登录、修改密码都会使旧会话失效。

## 部署到服务器

目标机器是 Ubuntu 24.04，2 核、大约 2GB 内存。这台机器上已经有别的代理，所以本应用：

- 默认只监听 `127.0.0.1:8787`
- 内存上限大约 512MB，照片一张一张处理
- 不占用 80 和 443，除非你明确打开可选的 Caddy

把仓库放到服务器上，例如 `/opt/couple-app`，然后：

```bash
cd /opt/couple-app
./deploy/install.sh
```

这一步用 Docker 构建并启动，端口映射是 `127.0.0.1:8787`。数据在 `./data`，备份在 `./backups`。需要 Docker Engine 和 Compose 插件。

不想用 Docker 时，先安装 Node.js 22，再执行：

```bash
sudo ./deploy/install.sh --systemd
```

这会创建系统用户 `couple`、安装依赖、注册 `couple-app.service`，并用同样的 `.env` 启动。内存上限同样是 512MB。

两种方式在 root 下执行时，都会写入 `/etc/cron.d/couple-app`：每天 04:15 备份一次。

常用命令：

```bash
docker compose logs -f app
docker compose restart app
sudo systemctl status couple-app
```

改 `.env` 之后要重启应用。可以改的项见 `.env.example`：端口、会话天数、单张大小、照片总数、默认时区和推送联系邮箱。不要把填了真实内容的 `.env` 提交到仓库。

## HTTPS

iPhone 的主屏幕应用和网页推送都需要正规域名上的 HTTPS，用 IP 加自签证书不够。

这台机器已经有 Caddy 或 Nginx 时，只加一个新站点，反代到 `127.0.0.1:8787`。应用在网站根路径，不要放到子目录。

Caddy 片段在 `deploy/Caddyfile.snippet`：

```caddy
couple.example.com {
	encode gzip
	request_body {
		max_size 20MB
	}
	reverse_proxy 127.0.0.1:8787
}
```

Nginx 片段在 `deploy/nginx.snippet`。需要把 `Host`、`X-Forwarded-For`、`X-Forwarded-Proto` 传给应用，并允许大约 20MB 的请求体。`.env` 里保持 `TRUST_PROXY=1`，这样才会在 HTTPS 下给 Cookie 加上 Secure。

只有在确认 80 和 443 没有被现有代理占用时，才用自带的 Caddy：

```bash
# .env 里设置 DOMAIN=couple.example.com
docker compose --profile caddy up -d
```

对应配置是 `deploy/Caddyfile`。证书由 Caddy 自动申请。想收到到期邮件时，按文件顶部的注释加上 `email`。

## 备份与恢复

备份包含数据库、Web Push 密钥、原图和缩略图，打成权限为 `0600` 的 zip，默认保留 14 天。备份目录不要放进 `data`。

```bash
./deploy/backup.sh
```

Docker 部署会在容器里执行；systemd 或本地直接用本机的 Node。定时任务就是调用这个脚本。

恢复会先停应用，把当前 `data` 改名为 `data-before-restore-时间戳`，再解压备份。确认没问题后再删那份旧目录。

```bash
./deploy/restore.sh backups/couple-20261027-041500.zip
```

应用必须先停掉再恢复，否则正在运行的进程还会拿着旧数据库。

网页里的「导出一份」是给当前登录者下载的：双方可见的内容、自己的私密日记，以及自己能看到的照片。对方的私密日记不在这份导出里。服务器备份则是完整数据，请保管好 zip 文件。

忘记密码时，在服务器上重设（密码从标准输入读入，不会出现在命令参数里）：

```bash
printf '%s' '新的密码至少八位' | node scripts/reset-password.js 用户名
```

Docker 里：

```bash
printf '%s' '新的密码至少八位' | docker compose exec -T -u app app node scripts/reset-password.js 用户名
```

该账号的旧登录会全部失效。

## 在两台 iPhone 上添加到主屏幕

两台手机都要做一遍。系统需要 iOS 16.4 或更高，在「设置 → 通用 → 关于本机」可以查看。

1. 用 Safari 打开你们的网址。从微信里打开无法添加到主屏幕。
2. 点底部的分享按钮，选择「添加到主屏幕」，再点「添加」。
3. 回到主屏幕，点「两个人」图标打开。一定要从图标进来。
4. 主屏幕里的登录和 Safari 不一定共用。如果看到登录页，用自己的账号再登录一次。
5. 点右上角「设置」，进入「开启通知」，再点「开启通知」，并允许系统提示。

应用里的「开启通知」页会检查：是不是从主屏幕打开、系统版本够不够、是不是 HTTPS。通知权限必须由你们亲手点按钮触发。

纪念日提醒在你们设置的时区、到达设定的小时之后发出（默认 9 点）。如果那天更晚才启动应用，当天仍会补发一次，不会重复。对方有新内容时，通知里只有一句「对方有新的照片 / 日记 / 清单」，不含正文。

## 清空与删除

设置页里：

- 「清空内容」会删掉日记、照片、清单记录和问答，两个账号还在。需要输入当前密码，并完整输入「清空内容」。
- 「删除全部并重新开始」会连账号一起删掉，网站回到第一次打开的样子。需要输入「删除全部」。

这两件事在网页里不能撤销。要恢复只能用服务器上的备份。

## 安全

- 整个站只有初始化时创建的两个账号。
- 所有改数据的接口都要登录，并带上本站自己的请求头，用来挡住其他网站发起的请求。
- 会话令牌只以哈希存在数据库里。Cookie 是 HttpOnly、SameSite=Lax；走 HTTPS 时再加上 Secure。
- 上传只接受 JPEG、PNG、WEBP、HEIC，并核对文件头。单张默认不超过 12MB，像素不超过约 4000 万，相册默认不超过 2000 张。
- 私密日记和它附带的照片，对方访问会得到「找不到」。
- 页面不允许被其他网站嵌入，也不加载任何外部脚本、字体或统计。
- 仓库里没有密钥。VAPID 密钥在第一次启动时写到 `data/vapid.json`，权限 0600。

磁盘上的数据库和照片是明文。请限制服务器登录，并保管好备份。

## 已知限制

- 只有两个账号。密码找回只能在服务器上用命令重设，没有邮箱验证。
- 登录 30 天后需要重新登录。
- iPhone 通知依赖 iOS 16.4、Safari「添加到主屏幕」，并且要从主屏幕图标打开。推送可能延迟，应用当天没运行过就不会发出那天的纪念日提醒。
- 错过的每日一问不能补答。答案在双方都提交后才能互看；揭晓后不能再改。
- 相册里的照片只有上传的人能删除。日记和清单附的照片不会出现在相册格子里。
- 网页导出不含对方的私密日记。完整备份在服务器上。
- 时区以站内设置为准，不跟手机自动变。
- HEIC 由内置解码处理。单进程一次只处理一张照片，大图会排队。
- 如果 `data/vapid.json` 丢了，会生成新密钥，两台手机都要重新开启通知。
- 不做端到端加密，不做位置共享，也不在后台定位。
